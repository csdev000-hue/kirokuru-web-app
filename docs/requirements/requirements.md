**AIプロジェクトマネージャー**  
**要件定義書**

Meeting → AI議事録 → AIチケット → プロジェクト管理

作成日：2026年9月7日  
版数：1.0

# **1\. 文書概要**

本書は、会議内容を起点として、AIによる議事録生成・課題抽出・チケット候補生成を行い、プロジェクト管理まで一連で支援するSaaS「AIプロジェクトマネージャー」の要件を定義する。

| 項目 | 内容 |
| :---- | :---- |
| サービス名 | AIプロジェクトマネージャー |
| 目的 | 会議後の議事録整理・アクション抽出・チケット登録工数を削減 |
| 対象 | PM、PL、開発チーム、業務チーム |
| 形態 | Web SaaS |
| 価値 | 会議内容を実行可能なチケットへ構造化 |

# **2\. 背景・課題**

* 会議後に決定事項・課題・担当者・期限を人手で整理している。  
* 議事録からBacklogやGitHub Issues等へ転記する作業が発生する。  
* 会議で決まった内容と作成されたチケットの対応関係が分かりにくい。  
* 会議内容が複数ツールに分散し、意思決定から実行までの追跡性が低い。

# **3\. サービスコンセプト**

「会議をしたら、AIが次にやるべきことまで整理する」。単なるプロジェクト管理ではなく、会議・議事録・AI分析・チケットをつなぐことを差別化ポイントとする。

| 段階 | 機能 |
| :---- | :---- |
| ①会議 | オンライン会議または会議情報を登録 |
| ②文字起こし | 会話内容をテキスト化 |
| ③AI議事録 | 要約・決定事項・課題・アクションを抽出 |
| ④AIチケット | アクション/課題から候補生成 |
| ⑤確認 | 人が編集・承認 |
| ⑥管理 | 一覧・ボード・詳細で進捗管理 |

# **4\. 対象範囲**

## **4.1 MVP対象**

* 認証・組織・プロジェクト管理  
* チケット一覧・検索・絞り込み  
* カンバンボード  
* チケット詳細・コメント・履歴  
* 会議登録・オンライン会議UI  
* AI文字起こし・議事録生成  
* AIチケット候補生成  
* 候補の確認・編集・承認  
* 会議・議事録・チケットの関連付け

## **4.2 MVP対象外**

* 高度な工数予測・自動計画  
* 複雑なガントチャート  
* 多言語同時通訳  
* 高度な録画編集  
* 外部PMツールとの完全双方向同期

# **5\. ユーザー・権限**

| ロール | 権限 |
| :---- | :---- |
| 組織Owner | 組織設定、メンバー管理、プロジェクト管理 |
| Project Owner | プロジェクト設定、メンバー管理、チケット管理 |
| Member | 担当チケット・会議・議事録の参照/編集 |
| Viewer | 参照中心 |

API側で認証・認可を実施し、組織・プロジェクト境界を厳格に分離する。IDを書き換えるだけで他プロジェクトへアクセスできないことを必須とする。

# **8\. AI要件**

## **8.1 AI議事録**

* 要約を生成  
* 決定事項を抽出  
* アクションアイテムを抽出  
* 課題を抽出  
* 保留事項を抽出  
* 明確な担当者・期限を候補化  
* 不明情報を推測で補完しない

## **8.2 AIチケット生成**

AIは構造化JSONで候補を生成し、サーバー側でスキーマ検証する。AIが直接チケット登録することは禁止し、人による確認・承認を必須とする。

| 項目 | 内容 |
| :---- | :---- |
| title | チケットタイトル（必須） |
| description | 実施内容・背景（必須） |
| type | Task / Issue / Bug等 |
| priority | High / Medium / Low等 |
| assignee | 担当者候補 |
| dueDate | 期限候補 |
| source | 元会議・議事録情報（必須） |

# **9\. オンライン会議**

* WebRTCベースで音声・映像通信  
* 多人数通信はSFUを利用  
* マイク、カメラ、画面共有、チャット、退出  
* 文字起こし状態を表示  
* 終了後に文字起こしを議事録生成へ連携  
* 会議基盤はVercel Functionsへ実装しない

# **10\. データ要件**

| エンティティ | 主な情報 |
| :---- | :---- |
| Organization | 組織 |
| User | ユーザー |
| OrganizationMember | 所属・権限 |
| Project | プロジェクト |
| ProjectMember | 所属・権限 |
| Ticket | 課題、状態、優先度、担当者、期限 |
| Meeting | 会議情報 |
| MeetingParticipant | 参加者 |

チケットには元会議ID等を保持し、会議→議事録→チケットのトレーサビリティを確保する。

# **11\. API要件**

| API | 概要 |
| :---- | :---- |
| GET/POST /api/organizations | 組織取得・作成 |
| GET/PATCH /api/organizations/:id | 組織取得・更新 |
| GET/POST /api/projects | プロジェクト取得・作成 |
| GET/PATCH/DELETE /api/projects/:id | 取得・更新・削除 |
| GET/POST /api/projects/:projectId/tickets | 一覧・作成 |
| GET/PATCH/DELETE /api/tickets/:id | 取得・更新・削除 |
| GET/POST /api/projects/:projectId/meetings | 会議取得・作成 |
| GET/PATCH/DELETE /api/meetings/:id | 取得・更新・削除 |
| POST /api/ai/generate-tickets | AI候補生成 |

# **12\. 非機能要件**

| 分類 | 要件 |
| :---- | :---- |
| セキュリティ | API側で認証・認可、テナント分離 |
| AI安全性 | JSON Schema等で検証、直接DB登録しない |
| 性能 | 通常操作は高速表示、AI処理は状態表示 |
| 監査性 | 変更履歴、AI生成元、承認者を追跡 |
| 拡張性 | 外部PMツール連携を追加可能 |
| レスポンシブ | PC中心、主要操作はタブレット/スマホ対応 |

# **13\. システム構成**

| レイヤー | 技術 |
| :---- | :---- |
| Frontend | Next.js / TypeScript |
| Hosting/API | Vercel / Next.js Route Handlers |
| Database | Neon PostgreSQL |
| ORM | Drizzle ORM |
| AI | Amazon Bedrock / Amazon Nova Lite |
| Storage | Amazon S3 |
| Source Control | GitHub |
| Online Meeting | WebRTC \+ SFU |

ブラウザからBedrock・DBへ直接接続せず、Vercel上のサーバーAPIを経由する。高負荷の非同期AI処理は将来的にSQS \+ Lambda等へ分離可能とする。

# **14\. AI処理フロー**

会議 → 文字起こし → AI議事録生成 → ユーザー確認 → AIチケット候補生成 → ユーザー編集/承認 → チケット登録 → プロジェクト管理。失敗時は元データを保持し、再実行可能とする。

# **15\. 業務フロー**

| No. | 利用者 | システム |
| :---- | :---- | :---- |
| 1 | プロジェクト作成 | Project登録 |
| 2 | 会議登録/開始 | Meeting作成 |
| 3 | 会議 | 音声・映像・チャット処理 |
| 4 | 会議終了 | 文字起こし確定 |
| 5 | 議事録生成 | AI分析 |
| 6 | 確認 | 修正・承認 |
| 7 | チケット生成 | AI候補生成 |
| 8 | 確認 | 選択・編集 |
| 9 | 登録 | チケット化 |
| 10 | 進捗管理 | 一覧/ボード/詳細 |

# **16\. 画面遷移**

ダッシュボード → 課題一覧 / ボード / 会議・議事録  
オンライン会議 → AI議事録確認 → AIチケット確認 → 課題一覧 → 課題詳細  
課題一覧 ↔ ボード → 課題詳細  
課題詳細 → 元会議/議事録

# **17\. MVP受入条件**

* ログインし、組織・プロジェクトを作成できる。  
* チケットを作成・編集・検索・絞り込みできる。  
* ボードでステータスを変更できる。  
* 会議内容を保持できる。  
* AIが決定事項・課題・アクションを抽出できる。  
* AIチケット候補を生成し、登録前に編集・確認できる。  
* 承認した候補をチケット登録できる。  
* チケットから元会議・議事録を追跡できる。  
* 認可外プロジェクトのデータへアクセスできない。

| 優先度 | 対象 |

| P0 | 認証、組織/プロジェクト、チケットCRUD、AI議事録、AIチケット、承認、権限 |
| P1 | オンライン会議、リアルタイム文字起こし、ボード、コメント、履歴、追跡 |

# **19\. 今後の拡張**

* GitHub Issues / Backlog / Slack連携  
* 次回会議アジェンダ自動生成  
* 未解決・期限超過課題のAI分析  
* 進捗リスク予測  
* チケットと仕様書・コード変更の関連付け  
* AIによるプロジェクト計画・タスク分解

# **20\. 重要な設計方針**

* AIは提案者、最終登録は人が承認する。  
* 会議→議事録→チケットの出典情報を保持する。  
* ブラウザからBedrock/DBへ直接アクセスさせない。  
* 認証と認可を分離し、プロジェクト単位のアクセス制御を徹底する。  
* MVPでは会議からチケット化までの一連の価値を最優先する。
